# 生成后的 HTML JSON 导入导出设计

日期：2026-08-24

## 目标

让 HtmlPasteGen 生成的独立 HTML 页面也能直接导入和导出 JSON，便于在多个页面之间迁移、备份和批量维护内容。导入失败时页面数据必须保持不变；导出内容只包含当前页面数据，不泄露浏览器本地存储键或界面临时状态。

## 范围

- 在生成页顶部操作区增加“导入 JSON”和“导出 JSON”按钮。
- 导出当前运行时的规范化 `model`，包括页面元信息、分组、条目、快捷键、备注、收藏状态和顺序。
- 导入使用文件选择器读取 UTF-8 JSON，经过结构规范化和完整校验后替换当前页面数据。
- 导入成功后写入现有本地草稿存储，并刷新导航、卡片、复制篮和编辑区。
- 导入失败时显示错误提示，不修改当前数据、不清空复制篮。
- 保留现有“导出最新版 HTML”功能；JSON 导入导出不改变 HTML 生成逻辑。

## 交互设计

### 导出

用户点击“导出 JSON”后，页面下载 `<安全页面名>.json`。导出的 JSON 使用 2 个空格缩进，并通过现有安全序列化逻辑处理 `<`、`>`、`&`、Unicode 行分隔符等字符。下载成功后在现有状态栏显示成功提示。

### 导入

“导入 JSON”按钮打开隐藏的 `accept="application/json,.json"` 文件选择器。选择文件后：

1. 读取文本并解析 JSON。
2. 使用现有文档规范化逻辑补齐默认字段。
3. 使用现有校验逻辑检查 schema 版本、分组/条目 ID、必填标题、快捷键格式及快捷键冲突。
4. 校验失败时提示具体错误，当前页面、复制篮和编辑状态保持不变。
5. 校验成功时弹出替换确认；用户确认后替换 `model`，清理旧条目对应的选择、排序和展开状态，保存并重新渲染。

导入成功后清空文件选择器的 value，使同一个文件可以再次选择；成功提示包含导入的分组和条目数量。

## 数据与安全

- 导入只接受 JSON 文件内容，不执行其中的 HTML 或脚本。
- 导入后的对象必须经过现有 `normalizeDocument` 和 `validateDocument`，不能直接写入运行时模型。
- 导出的对象不包含 `storageKey`、主题偏好、复制篮排序、卡片展开集合、拖拽状态等页面运行时临时状态。
- 原有 localStorage 失败降级和错误提示机制继续生效；无法自动保存时，仍允许导出 JSON/HTML 手动备份。

## 兼容性

- 生成页普通浏览模式和编辑模式均可使用 JSON 操作。
- 移动端沿用现有顶部操作按钮的换行布局。
- 不引入外部依赖，不增加服务器端路由。
- 生成器工作台已有的 JSON 导入导出行为保持不变。

## 测试策略

- 静态契约测试确认生成页包含按钮、文件输入、事件绑定和导入/导出函数。
- 核心生成测试确认生成后的 HTML 包含 JSON 控件，且生成页运行脚本可通过语法检查。
- 浏览器试用验证：导出当前数据、导入有效 JSON、拒绝无效 JSON、确认替换，以及导入失败不改变当前内容。
- 回归运行现有 HtmlPasteGen 核心/UI 测试与 Linux 构建。
