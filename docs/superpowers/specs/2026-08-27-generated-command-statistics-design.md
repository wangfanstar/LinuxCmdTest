# 生成 HTML 命令统计面板设计

## 目标

在 `HtmlPasteGen.html` 生成的快捷复制页面中增加命令统计信息。统计面板默认折叠，用户点击标题后展开查看；统计内容应能随着搜索、筛选、收藏、导入 JSON 和页面编辑实时更新。

## 交互设计

- 固定工具栏下方、命令内容区域上方显示“命令统计”折叠面板。
- 面板使用原生 `<details>` / `<summary>`，默认不设置 `open`，因此首次打开页面时保持折叠。
- 摘要行显示总命令数，点击摘要行即可展开或收起，无需额外按钮。
- 展开后显示两部分：
  - 指标卡：全部命令、当前搜索结果、分组数、收藏数、快捷键数、快速链接数。
  - 分组汇总：每个分组显示根节点数量和递归后的命令总数，子节点会计入所属分组。
- 搜索或收藏筛选时，“全部命令”保持全量基准，“当前搜索结果”反映当前可见结果，避免用户误解统计口径。
- 没有分组时显示空状态；统计更新不改变面板当前的展开/收起状态。

## 技术方案

- 仅修改生成 HTML 模板及其内嵌运行时，不新增外部依赖，也不改变现有 JSON schema。
- 在生成模板中增加稳定的 DOM 标识：`generated-statistics`、`statistics-summary-count`、`statistics-content` 和 `statistics-groups`。
- 在生成运行时增加 `renderStatistics(groups)`：
  - 使用现有递归 `allItems()` 计算全量统计。
  - 使用当前 `visibleGroups()` 的递归展平结果计算筛选结果。
  - 对每个原始分组递归展平其 `items`，计算分组总量，并使用 `textContent` 创建节点，避免用户数据进入 HTML 字符串。
- 在现有 `renderMainOnly()` 中调用统计渲染，使搜索、筛选、导入和编辑等已有刷新路径自动更新统计。
- CSS 使用现有主题变量和响应式断点；桌面端指标卡横向排列，窄屏自动换行。面板不采用 fixed/absolute 定位，避免遮挡命令内容。

## 数据流与边界

1. 页面加载或模型变化时，`renderMainOnly()` 获得当前可见分组。
2. `renderStatistics()` 从当前模型和可见分组计算指标。
3. 统计内容通过 DOM 节点重建；异常数据按已有迁移/规范化结果处理，不额外修改模型。
4. 当统计 DOM 不存在（例如未来的旧模板）时，函数安全返回，不阻塞主页面渲染。

## 测试策略

- 生成 HTML 静态契约测试：验证折叠面板标记、稳定 ID、统计渲染函数、全量/当前结果文案和分组汇总标记均存在。
- 生成运行时语法测试：继续使用现有 `vm.Script` 检查内嵌脚本可解析，并验证所有事件监听目标 ID 存在。
- UI 静态测试：验证统计面板默认折叠（`details` 无 `open`）、样式响应式规则和运行时挂载点存在。
- 回归验证：运行现有 HTML、网络库、索引导航、重启脚本测试，并执行 `wsl make -B`。

## 非目标

- 不在编辑器页面增加同一套统计面板。
- 不修改 v1/v2 JSON 兼容逻辑或导入导出格式。
- 不增加后端 API、数据库或第三方统计服务。
