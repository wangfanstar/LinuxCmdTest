# 编辑器分组与条目跨层级转换设计

## 目标

在 `HtmlPasteGen.html` 编辑器左侧结构树中打通“分组”和“条目”的层级边界：分组可以降级为上一分组中的顶级条目，条目可以升级为独立分组。转换必须保留已有复制内容和子树，遵守最多四级条目的限制，并继续兼容旧 JSON 导入。

## 推荐交互

采用“连续层级按钮 + 右键直达”的双入口方案：

- 分组行在现有上移、下移按钮旁增加“降级”按钮，提示文字为“降级为上一分组的条目”。第一个分组没有上一个分组，因此按钮禁用。
- 分组右键菜单增加“降级为上一分组的条目”。不可执行时保留菜单项但禁用，并通过标题说明原因。
- 条目的现有“提升层级”按钮形成连续操作：
  - 二至四级条目仍按现有规则提升一级。
  - 顶级条目再次提升时，转换为独立分组。
- 任意层级条目的右键菜单增加“直接升级为分组”，允许一次操作跨越中间层级。
- 转换前显示确认框，明确源标题、目标位置和受影响的子条目数量；用户取消时不修改文档。
- 转换成功后自动选择目标分组、展开相关导航、聚焦被转换条目、保存草稿并显示成功提示。

该方案兼顾可发现性和效率：新用户可以沿用可见的层级按钮，熟练用户可以用右键一步完成跨层级转换。

## 数据转换规则

### 分组降级为条目

给定分组 `groups[index]`：

1. 仅当 `index > 0` 时允许转换，目标为 `groups[index - 1]`。
2. 在目标分组 `items` 末尾创建一个新条目：
   - `id` 使用新的条目 ID。
   - `title` 使用原分组标题。
   - `content`、`shortcut`、`link`、`note` 使用条目默认空值。
   - `favorite` 为 `false`。
   - `collapsed` 沿用原分组折叠状态。
   - `children` 直接接收原分组的完整 `items` 子树。
3. 从文档顶层 `groups` 中移除原分组。
4. 原分组内所有条目的对象、ID、复制内容、快捷键、链接、备注、收藏状态和子树顺序保持不变。

因为增加了一个条目包装层，只有当 `1 + 原分组最高条目子树高度 <= MAX_ITEM_DEPTH` 时才能转换。超过四级时必须在修改文档前拒绝操作，并提示“降级后会超过最多 4 级”。空分组可以降级为一个无子条目的空内容条目。

### 条目升级为分组

给定任意层级条目及其当前分组：

1. 从原兄弟列表中移除该条目及完整子树。
2. 在当前分组之后创建新分组：
   - `id` 使用新的分组 ID。
   - `title` 使用原条目标题。
   - `collapsed` 为 `false`，确保转换结果立即可见。
   - `items` 只包含原条目本身。
3. 原条目的 ID、复制内容、快捷键、链接、备注、收藏状态、折叠状态和全部子条目保持不变。
4. 条目从嵌套位置升级后成为新分组中的顶级条目，因此不会增加树深度，也不会触发四级限制。

条目标题同时作为新分组标题和组内第一条标题，是有意的无损设计：分组数据模型不能保存复制正文，因此必须保留原条目本体。

## 核心模型边界

在 `HtmlPasteGenCore` 增加两个纯数据操作：

- `demoteGroupToItem(document, groupId)`
- `promoteItemToGroup(document, itemId)`

两个函数统一返回 `{ ok, reason, group, item }` 形式的结果：

- 所有目标查找、首组限制、数组结构和深度限制在修改前完成。
- 失败时文档必须保持字节级等价，不产生部分移动。
- 成功时只移动现有子树并创建边界节点的新 ID，不复制或清空快捷键。
- 核心函数不调用 DOM、确认框、渲染或草稿保存，便于独立测试和复用。

JSON 继续使用 `schemaVersion: 2`，不增加字段、不改变迁移规则。旧版 v1 和当前 v2 JSON 仍通过现有 `migrateDocument()`、`normalizeDocument()` 导入。

## 编辑器数据流

1. 可见按钮或右键菜单产生 `demote-group-to-item` / `promote-item-to-group` 动作。
2. 运行时从当前 `state.document` 重新解析分组或条目位置，生成确认文案。
3. 用户确认后调用核心转换函数。
4. 失败时只使用 `announce(reason, 'warning')` 提示，不重新渲染或保存。
5. 成功时更新 `selectedGroupId`、`expandedNavGroupIds` 和 `expandedNavNodeIds`：
   - 分组降级后选择上一个分组并展开新包装条目。
   - 条目升级后选择新分组并展开该分组。
6. 调用现有 `renderAll()`、`scheduleDraftSave()` 和聚焦流程完成界面同步。

上下文菜单的可用性在每次打开时根据当前文档重新计算，避免导航重绘后使用旧对象引用。

## 错误处理

- 第一个分组：禁用降级并提示“第一个分组没有可接收它的上一分组”。
- 找不到目标分组或条目：返回“目标不存在，请刷新后重试”，不修改文档。
- 分组条目结构无效：返回结构错误，不尝试修复或部分转换。
- 降级后超过四级：返回明确的深度提示，不移动任何节点。
- 用户取消确认：静默结束，不保存草稿、不显示成功提示。

## 测试策略

### 核心模型测试

- 非首分组降级后位于上一分组末尾，包装条目字段正确，原子树 ID、内容和顺序保持不变。
- 首分组降级失败且文档不变。
- 含四级条目的分组降级失败且文档不变。
- 任意层级条目升级后，新分组位于源分组之后，原条目完整成为第一条。
- 顶级和嵌套条目升级均保持快捷键、链接、备注、收藏和子树。
- 不存在的 group/item ID 失败且文档不变。
- 转换后的文档通过现有 `validateDocument()` 和 JSON 构建测试。

### UI 契约与浏览器测试

- 分组可见按钮和右键菜单包含降级动作，首分组状态禁用。
- 顶级条目的提升按钮可用且文案表明会升级为分组；嵌套条目仍执行普通提升。
- 条目右键菜单包含直接升级动作。
- 确认、成功提示、选择、展开、聚焦和草稿保存调用存在。
- 浏览器实测分组降级、嵌套条目直接升级、顶级条目连续提升以及深度拒绝路径。

### 完整回归

运行全部 HtmlPasteGen Node 测试、网络库接口测试、首页导航测试、重启脚本测试、`git diff --check` 和 `wsl make -B`。

## 非目标

- 不修改生成 HTML 页中的导航或编辑模式；本功能只作用于 `HtmlPasteGen.html` 生成器编辑器。
- 不增加拖拽跨分组转换。
- 不提供多步撤销历史；继续依赖确认框、自动草稿和 JSON 导出保障数据安全。
- 不改变四级条目上限或 JSON schema 版本。
