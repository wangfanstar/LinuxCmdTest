# HtmlPasteGen 可调宽度工作台设计

## 目标

改善 `HtmlPasteGen.html` 编辑工作台的桌面可读性：扩大整体页面和左侧内容结构导航，并允许用户用鼠标按需调整导航宽度，同时不牺牲编辑区、预览区和窄屏布局的可用性。

## 已确认的产品决策

- 采用 B 方案：保留内容结构、录入编辑、成品预览三栏。
- 工作台桌面最大宽度由当前约 1540px 提升到约 1880px。
- 左侧导航默认宽度约 330px，可在 260–520px 范围内调整。
- 导航宽度通过工作台与编辑区之间的垂直分隔条调整；拖动使用 Pointer Events，避免鼠标按下后离开分隔条导致失控。
- 双击分隔条恢复默认宽度。
- 分隔条提供键盘操作：左右方向键按步长微调，Shift+方向键按大步长调整，Home/End 跳到最小/最大宽度。
- 当前宽度写入浏览器本地存储；读取失败或值非法时回退到默认宽度，不影响页面加载和内容草稿。
- 窄屏（现有单栏断点）不显示分隔条，也不应用桌面宽度限制；现有移动端面板切换逻辑保持不变。
- 不修改 JSON schema、生成 HTML 数据结构或现有内容模型。

## 布局结构

桌面端 `.workspace` 使用四列网格：

1. 内容结构导航：`minmax(260px, var(--structure-width))`；
2. 可操作的 8px 左右分隔条；
3. 录入与编辑：设置合理的最小宽度并占据主要剩余空间；
4. 成品预览：设置独立最小宽度，持续可见。

工作台自身使用更大的 `max-width`，但仍保留左右页面边距。窗口变窄到现有移动端断点时，网格恢复单栏，分隔条从布局中隐藏。

分隔条是可聚焦的 `button`，具有清晰的中文 `aria-label`、`title` 和 `role` 语义；视觉上显示一条可拖动的竖线，不承载额外业务操作。导航面板继续使用现有独立滚动区域，因此长目录只滚动左栏。

## 宽度状态与交互

- 常量：默认 330px，最小 260px，最大 520px，键盘小步长 16px，大步长 80px。
- 初始化时从 `localStorage` 读取数值，使用有限数字校验和边界夹紧；读写异常只静默回退，不阻塞编辑器。
- `pointerdown` 开始拖动并捕获指针；`pointermove` 根据工作台左边界计算目标宽度并夹紧；`pointerup`/`pointercancel` 结束拖动并保存最终值。
- 键盘调整立即更新 CSS 自定义属性、`aria-valuenow` 和状态提示；Home/End 分别设置边界值。
- 双击恢复默认值，更新视觉布局、持久化值和可访问状态，并通过现有提示区域反馈。
- 调整只改变布局，不改变当前选中分组、条目内容、导航展开状态或 JSON 数据。

## 响应式与错误处理

- 桌面布局为主要目标；已有 960px/900px/620px 媒体查询继续负责窄屏切换。
- 在单栏模式下，分隔条 `display:none`，工作台宽度变量不参与计算，避免移动端出现横向滚动。
- 当拖动或键盘调整导致编辑区/预览区可能不足时，导航宽度被最大值限制；同时为编辑区和预览区设置最小列宽。
- 缺失 DOM、旧浏览器不支持 Pointer Events、`localStorage` 被阻止等情况都应退化为固定默认布局，页面其他功能照常工作。

## 测试与验收

自动化测试增加以下契约：

- 工作台最大宽度、四列结构、导航宽度 CSS 变量、最小/最大边界和窄屏隐藏规则存在。
- 分隔条具有按钮语义、可访问标签、双击恢复、Pointer Events、键盘 Home/End/方向键处理。
- 本地存储键、读取校验、边界夹紧及失败回退逻辑存在。
- 现有核心、UI、网络库、首页导航、重启脚本和 bundle API 测试继续通过。

真实页面检查覆盖：桌面默认宽度、鼠标拖动、双击重置、键盘调整、刷新后的宽度恢复、左栏独立滚动、窄屏单栏及控制台无新增错误。

## 不在本次范围内

- 不改变生成 HTML 的布局或生成页面运行时。
- 不新增服务端接口或修改网络库文件格式。
- 不引入第三方 UI 依赖。
- 不重构现有编辑器数据模型或移动端面板切换。
