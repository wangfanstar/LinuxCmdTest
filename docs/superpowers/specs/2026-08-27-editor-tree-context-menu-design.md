# 编辑器左侧树导航右键菜单设计

## 目标

在 `HtmlPasteGen.html` 编辑器左侧的分组/标题层级树上增加右键上下文菜单，减少用户在深层条目间复制、粘贴和删除时的操作成本，同时保持现有树层级、快捷键和 JSON 兼容逻辑不变。

## 交互设计

- 用户在左侧分组标题或任意条目标题处右键时，阻止浏览器默认菜单并打开页面内上下文菜单。
- 条目菜单提供：
  - 复制条目：复制当前条目及完整子树到内部剪贴板。
  - 粘贴为子条目：将剪贴板内容作为当前条目的最后一个子条目插入；达到 4 级时禁用。
  - 粘贴为同级条目：将剪贴板内容插入当前条目之后；根节点条目可用。
  - 删除条目：删除当前条目及全部子条目，继续使用现有确认提示。
- 分组菜单提供：
  - 复制分组：复制分组及其完整条目树到内部剪贴板。
  - 粘贴分组：在当前分组之后插入副本。
  - 删除分组：删除分组及内容，继续使用现有确认提示。
- 粘贴操作使用结构化内存剪贴板，不请求系统剪贴板权限；每次粘贴都深拷贝并生成新的分组/条目 ID，避免 ID 冲突。
- 菜单显示当前上下文标题和可用性；点击菜单外、按 `Escape` 或执行操作后自动关闭。
- 删除和粘贴完成后沿用现有 `renderAll()`、草稿保存和状态播报流程；菜单本身不改变编辑器的选择状态。

## 技术方案

- 在编辑器运行时维护：
  - `treeClipboard = { kind: 'item' | 'group', value: clonedValue } | null`
  - `contextMenuState = { kind, groupId, itemId } | null`
- 在 `renderItemTree()` 中为每个 `.tree-node-row` 设置 `contextmenu` 监听，并在分组 `.group-row` 标题选择器上设置同样监听；使用 `dataset` 传递 group/item ID。
- 增加单一 `renderTreeContextMenu()`，菜单节点通过现有 `createElement` 创建，所有用户标题使用 `textContent`，菜单定位限制在视口范围内。
- 增加 `handleTreeContextAction(action)`：
  - 调用已有 `core.cloneItemTree`、`core.itemDepth`、`core.findItemLocation` 和 `core.MAX_ITEM_DEPTH`。
  - 复制前清除复制副本中的快捷键，避免粘贴后产生冲突；复制分组同时生成新分组 ID。
  - 粘贴条目时校验目标深度和目标存在性，失败只播报提示，不修改文档。
  - 成功操作统一调用 `updateAfterAction()` 或现有分组选择/聚焦流程。
- 通过事件委托监听 `document` 的 `click`、`keydown` 和 `contextmenu`，保证菜单在重新渲染后仍可用，并且不会与已有按钮事件重复触发。
- 菜单样式使用现有主题变量，采用 `position: fixed`，带阴影、焦点样式和窄屏边界修正；不影响左侧导航滚动条。

## 数据流与边界

1. 右键事件解析最近的分组/条目节点，保存上下文并渲染菜单。
2. 用户选择操作后从当前文档重新查找目标，避免菜单打开期间文档变化导致旧引用失效。
3. 复制只更新内存剪贴板；粘贴/删除更新 `state.document`，随后渲染、保存草稿并播报结果。
4. 条目粘贴为子条目时，目标深度 + 副本树高度不得超过 `MAX_ITEM_DEPTH`；同级粘贴按目标所在兄弟列表插入。
5. 未复制内容时粘贴菜单禁用；上下文不存在时菜单立即关闭。

## 测试策略

- UI 静态契约测试：验证上下文菜单容器、条目/分组动作标记、剪贴板状态、`contextmenu` 监听、Escape/外部点击关闭逻辑和最大深度校验存在。
- 核心模型测试：验证复制树后 ID 不重复、快捷键被清空、子条目/同级粘贴位置正确、深度上限拒绝粘贴、分组副本插入位置正确。
- 生成页回归：确保生成 HTML 运行时没有编辑器上下文菜单代码或后端 API 依赖。
- 完整验证：运行现有 Node 测试、`git diff --check` 和 `wsl make -B`。

## 非目标

- 不使用系统剪贴板或跨浏览器页面共享剪贴板。
- 不修改生成 HTML 页的复制菜单；本功能只作用于 `HtmlPasteGen.html` 编辑器左侧树导航。
- 不新增后端接口、JSON 字段或第三方依赖。
